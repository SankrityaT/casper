How Casper works underneath

One small server (the hub) does the work and holds no state. The room itself lives in Terse actors, so it survives anything. Agent Relay carries every message between agents and people. Agents join from laptops (Claude Code, Codex) or run on their own computers (boat).

One run, start to finish

The whole system in one picture, then one afternoon of work played through it: a call turns into tasks, agents claim and talk, Stretch routes, Fatso remembers, Salem works on its own computer, people take over and approve, things ship, and the hub dies and comes back. 1b · Built to swap parts

Every outside service sits behind one small interface in the hub, so we can change providers without touching the rest. Each module is stateless; anything that must survive lives in an actor. That’s what makes it scale: run more hubs, and the actors keep everyone in order.

Runner real Saturday

Where an agent runs. start · send · interrupt · stop · liveView

  • laptop: Claude Code / Codex joined with the knock command
  • boat: a VM running Claude Code or Codex for you
  • agent-browser in the VM: the agent drives Chrome through its MCP; its WebSocket stream is the live view and Take over
  • later: Superserve, our own VMs

Memory + knowledge real Saturday

gbrain (Garry Tan’s open-source company brain) is the store: pages, linked facts, hybrid search, remember / forget. One brain per wing. Fatso is the only writer; agents read through the hub, which filters by who can see what. See docs/knowledge.md.

  • one gbrain process, next to the hub (PGLite takes one writer). Agents get results in their prompt or from casper_memory_search
  • no gbrain mcp expose or Tailscale this weekend
  • needs Bun ≥ 1.4.4; boat VMs ship 1.3.14, so it doesn’t run there

Triage: Jev stretch

Stretch’s brain. For any message nobody @mentioned, Jev (TypeSafe) scores in ~100 ms which agent it’s for, whether anyone should answer, and how (answer, investigate, react, stay quiet). Below a confidence bar, the room stays quiet. Off = only @mentions get answers.

  • Choice: which agent · Score: how useful / urgent · Noul: yes/no (“does anyone need to answer?”)
  • ~68% accurate in its own numbers: act when sure, ask when unsure, stay quiet when low
  • jev-1.14.0 pinned · not a sponsor

2 · What each actor holds

Actors are the only place state lives. Each one handles a single request at a time, so “two agents grab the same task” can’t both win. That one rule gives us claim-once, approvals where only the first click counts, and the same order on every screen.

Room real Saturday

Tables (SQLite)
events    (seq, id unique, type, by, payload, at)
tasks     (id, title, status, claimed_by)
claims    (task_id → agent, files[])
locks     (resource → agent, expires_at)
approvals (id, for_user, summary, diff, status, decided_by)
hops      (thread → count)
Methods
  • append(event): numbers it, ignores duplicate ids (Relay can send twice)
  • claim(task, agent) → yours or taken by Jack
  • openApproval / decide(id, user): role check, first click wins
  • since(seq): catch-up for late joiners and for the hub after a restart
  • heartbeat(agent): resets the “stuck” timer
Alarms
  • No progress for 2 min → stuck card (Steer / Take over / Stop)
  • Approval unanswered → ask the next person, or expire and say so
  • 6 agent-to-agent hops with no person → pause both, “Step in?”
Pushed live to screens

summary {tasks, claims, needsYou[], agents[], lastSeq} plus broadcast of each new event

Agent real

State
  • owner, kind (Claude Code, Codex, ours)
  • status + mood (calm, alert, worried, asleep, happy)
  • “working on” line from hooks
  • computer id, last activity
  • rights: Can read / Can act / Asks first for …

Mood drives the plush face on the canvas.

Space + Org seeded

State
  • members and roles (Owner, Editor, Viewer)
  • agents added to the space
  • usage events (tokens, VM seconds)

Joining a coding agent (one command per person)

The hub mints a room pass for each agent: one Casper token for MCP and hooks. Agents never get a Relay key. The hub holds the Relay identities and delivers each agent’s inbox through the prompt hook, as extra context on its next turn.

claude mcp add --transport http casper https://hub…/mcp \
  --header "Authorization: Bearer cp_room_…"
# hooks → https://hub…/hooks
#   UserPromptSubmit: ~10 memories + inbox messages
#   PreToolUse:       blocks git push unless the hub holds an approval for that SHA (fails closed)
#   PostToolUse/Stop: progress on the card, claim lease renewed

Why no Relay MCP on laptops: its documented MCP takes the workspace (admin) key, and Relay has no per-channel limits. MCP runs stateless (no session id), so a hub restart doesn’t break connected agents.

Versions to pin

Bun ≥ 1.4.4 (gbrain; Terse needs 1.4.2) · gbrain at a pinned commit · jev-1.14.0 · terse-sdk@0.14.7 · terse-cli@0.14.7 · @agent-relay/sdk@14.0.0 · Node ≥ 22. Both projects ship several releases a day, so nothing on @latest Saturday morning.
